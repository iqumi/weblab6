# Список задач — лабораторная №9

**Автор:** Сергей <фамилия, отчество>, группа <номер группы>

To-Do на Vue 3, Vite и TypeScript с регистрацией, входом, личными списками задач и страницей
«О приложении». Состояние хранится в Pinia (`useUserStore`, `useTodoStore`) и сохраняется в
`localStorage` через `pinia-plugin-persistedstate`. Страницы и ограничение доступа обеспечивает
Vue Router (`createWebHashHistory`, поэтому статическому хостингу не нужна настройка
перенаправлений). Код проверяют `vue-tsc`, ESLint (flat config) и Prettier.

**Опубликованная версия:** <ссылка на GitHub Pages>

**Версия Node.js:** 22 LTS и выше.

## Команды

| Команда                | Назначение                                                       |
| ---------------------- | ---------------------------------------------------------------- |
| `npm ci`               | установка зависимостей строго по `package-lock.json`             |
| `npm run dev`          | запуск в режиме разработки                                       |
| `npm run type-check`   | проверка типов: `vue-tsc` для приложения, `tsc` для Vite-конфига |
| `npm run lint`         | проверка ESLint, предупреждения считаются ошибками               |
| `npm run format:check` | проверка форматирования Prettier                                 |
| `npm run check`        | все три проверки подряд, файлы не меняются                       |
| `npm run lint:fix`     | автоисправление ESLint                                           |
| `npm run format`       | форматирование проекта Prettier                                  |
| `npm run build`        | `npm run check`, затем сборка Vite в `dist/`                     |
| `npm run preview`      | просмотр собранной версии                                        |

## Что проверяет сборка

`npm run build` сначала запускает `npm run check`: проверку типов, ESLint и Prettier. Если любая
проверка не прошла, команда останавливается и `vite build` не выполняется.

Vite только преобразует TypeScript в JavaScript и не проверяет типы. Типы проверяют `vue-tsc`
(код приложения, `<script>` и шаблоны `.vue`) и `tsc` (`vite.config.ts`, который выполняется в
Node.js). Поэтому проверка типов вынесена в отдельный шаг перед сборкой.

## Хранение данных

Формат и ключи `localStorage` не менялись по сравнению с лабой №7 (`todo-list:users`,
`todo-list:todos`, `todo-list:theme`), поэтому пользователи и задачи прежней версии читаются
после переноса. Загруженные данные проверяются при чтении: записи неверного формата и дубликаты
отбрасываются.

## Учебная авторизация

Бэкенда нет: пользователи, пароли и состояние входа хранятся только в браузере и доступны
любому скрипту страницы. Механизм не защищает реальные данные. Для проверки используйте только
вымышленные email и учебные пароли, которые нигде больше не применяются.

## Порядок проверки

1. Откройте `#/todo` без входа — произойдёт перенаправление на страницу входа.
2. На странице регистрации проверьте ошибки: неверный формат email, разные пароли, повторный email.
3. Зарегистрируйте пользователя `first@example.com`, войдите, добавьте несколько задач.
4. Обновите страницу — вход и задачи сохраняются.
5. Нажмите «Выйти», зарегистрируйте и войдите как `second@example.com` — список пуст.
6. Выйдите и снова войдите как `first@example.com` — видны только его задачи.
7. Если в браузере остались данные версии лабы №7, откройте приложение там же: аккаунты и задачи
   должны войти без повторной регистрации.
8. Проверьте неверный пароль при входе и страницу «О приложении».
